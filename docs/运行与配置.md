# 运行与配置

## 环境

- Java 21；前端开发使用兼容Vite 7的Node版本，现有前端Dockerfile使用Node 24。
- PostgreSQL；应用库与测试库分离，测试使用create-drop，不能连接业务数据库。
- Docker CLI及可用守护进程。可信后端控制进程需要能调用Docker；模型命令在隔离容器中执行。现有后端Dockerfile只包含JRE，不提供完整Docker控制通道。

## 本地数据库与后端

创建专用数据库 `dsh`。通过环境变量 `DB_USER`、`DB_PASSWORD` 提供本地数据库账号；连接地址可用Spring标准配置 `SPRING_DATASOURCE_URL` 覆盖。

从仓库根进行Docker构建：

```powershell
docker run --rm -v "${PWD}/backend:/workspace" -w /workspace maven:3.9-eclipse-temurin-21 mvn -B -DskipTests package
docker build -t dsh-sandbox:latest ./sandbox
```

已有源码配置默认监听127.0.0.1:8080，默认数据库为localhost:5432/dsh。在已配置好Docker CLI和数据库的可信本机环境启动后端控制进程：

```powershell
java -jar backend/target/dsh-backend-0.1.0-SNAPSHOT.jar
```

## 前端开发

现有Vite配置以本机后端为代理目标。进入 `frontend` 安装本机开发依赖并启动开发服务：

```powershell
cd frontend
npm ci
npm run dev
```

交付构建可使用已有前端Dockerfile。容器化nginx需要能够访问可信后端的地址，不能假设容器中的127.0.0.1是宿主机；本项目未交付自动部署编排。

## 模型与凭据

先通过工作台创建模型配置。Fake模型适合不调用真实供应商的演示。DeepSeek配置使用provider `deepseek` 和凭据引用，例如 `deepseek`。

环境变量存储通过 `DSH_CREDENTIAL_<引用大写>` 查询凭据；引用deepseek对应 `DSH_CREDENTIAL_DEEPSEEK`。密钥只在本机凭据配置中设置，不写入代码、配置样例、日志或Git。不要将私有运行目录注册为模型可操作项目。

## 多 Agent 与强验收

相关开关默认关闭。强路径需明确设置：

```properties
dsh.orchestration.enabled=true
dsh.orchestration.executable-checks-enabled=true
dsh.orchestration.strong-runtime-enabled=true
```

同时需要项目／工作区之外的可信Host检查目录，以及根验收模式和逐任务完整v2描述确认；仅打开开关不等于已具备可执行检查。

关闭强运行不会将既有强任务降级到摘要或关键词验收。执行状态未知时，显式恢复可能将本代根任务结束为CANCELLED/CHECK_RECOVERY_FENCED，不自动重复运行未知副作用。
